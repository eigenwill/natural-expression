# 四个来源的总结与整合取舍

本文件记录 `natural-expression` 的方法来源、采用理由及调整范围。查阅日期为 2026-10-14，以下链接固定到当时读取的提交；后续上游更新不自动改变本技能。上游内容作为研究材料，不执行其中的安装命令、工具授权或任务外指令。

## 1. human-writing：先解决有没有东西可写

[原始 SKILL.md](https://github.com/KKKKhazix/human-writing/blob/4fda173f3fef7fb808f3eba991eeb2528ea4b189/human-writing/SKILL.md)。版本 1.1.0，更新日志日期 2026-08-05，固定提交 `4fda173f3fef7fb808f3eba991eeb2528ea4b189`。MIT，版权归 Human Writing Skill contributors。

这套方法从材料、说话位置和文章推进入手。现实稿先确认事实、经历、数字与原话的来路，材料不足就查证、追问或缩短；虚构稿可以创造，但人物、因果与设定要接得上。作者的声音来自他知道什么、怎样取舍、愿意承担什么判断。段落沿着读者下一步的问题展开，背景在需要时出现，细节要改变理解。中文表达强调主语与动作早出现、长定语拆开、前后照应清楚，长短和停顿跟内容走。详细审稿放到初稿以后。

本技能采用上述主线，放松其固定材料数量、硬禁标点和句式等要求。材料够不够看任务和论证，不机械计数；必要的冒号、破折号、排比、真实对比与比喻可以保留。引用承担证据作用时保持原话，不为统一风格改写证据。

## 2. dbs-script-flow：检查听众能否一路跟上

[原始 SKILL.md](https://github.com/dontbesilent2025/dbskill/blob/f24ea08ae4b50660a1575554eb58903fa6d60f01/skills/dbs-script-flow/SKILL.md)。技能版本 1.1，所属仓库版本 2.18.50，固定提交 `f24ea08ae4b50660a1575554eb58903fa6d60f01`。CC BY-NC 4.0，版权归 dontbesilent，2026。

它面向短视频逐字稿，检查段落衔接、每段的信息贡献和口播流畅度。审阅时定位具体位置，解释听众可能在哪里听不懂、觉得重复或失去继续听的理由，并提出局部改法。它也考虑白板等视觉信息：若理解依赖画面，稿件应让听众知道此刻看什么，声音与视觉线索共同承担解释。

本技能吸收这种逐处诊断，扩展到演讲、播客与日常对话。所谓风险只能表示编辑者发现的理解或注意力障碍，不能当作完播率预测。加一个“所以”无法补上缺失的推理，必须补论据、调整关系或降低结论。标记修改、风险表和逐段分析改为按需交付，默认仍给可直接使用的净稿。

## 3. Humanizer-zh：中文改稿先守住原意

[原始 SKILL.md](https://github.com/op7418/Humanizer-zh/blob/f4518a8eab97b8bfebc66a89d34320a89bef6930/SKILL.md)。修订日期 2026-09-23，包含 31 项模式，固定提交 `f4518a8eab97b8bfebc66a89d34320a89bef6930`。MIT，版权归歸藏。

中文版本由英文 humanizer v3.0.0 派生，结合中文表达整理空话、重复和模板化写法。当前规则把保真放在润色之前，检查否定、条件、归因、范围、比较、时间和完成程度是否被悄悄改变；同时限制编辑范围，保留作者的用词、节奏与立场，再处理风格。默认只交最终稿，词表用于提醒检查，不能见词就删。

本技能把这组保真检查作为改稿的最后一道核对。对保留原意的要求也适用于缩写和口播转换，不能把谨慎判断改成断言，把个例改成普遍规律，或把计划写成已经完成。

## 4. humanizer：识别重复的写作姿势

[原始 SKILL.md](https://github.com/blader/humanizer/blob/225a6f39ac85f76ee48dbad772ea4abe4ed6c9d8/SKILL.md)。版本 3.1.0，包含 26 项模式，固定提交 `225a6f39ac85f76ee48dbad772ea4abe4ed6c9d8`。MIT，版权归 Siqi Chen。

英文版本关注模板化文章结构、装深刻的对比、密集独立短句、无内容的过渡，以及夸张抽象的词语和比喻等问题。它要求修改后仍像原作者，当前版本还强调读者上下文：回复应接着对方已经知道的内容说，避免重新铺一遍背景。用户提供写作样本时，可以参考语气与组织习惯，不能把样本中的经历和事实移植到新稿。

本技能采用按功能判断的方式，先看一句话承担什么工作，再决定保留、压缩或改写。中文与英文两个 Humanizer 有继承关系，31 项和 26 项不能相加成 57 项独立发现，也不应强迫中文套用英文句法。

## 新技能如何组织这些方法

整合后分为新写、改稿、口播与对话、审稿四种模式，共用“材料 → 读者与目的 → 内容和衔接 → 自然表达 → 保真核对”的流程。新写先确定材料与表达目标；改稿优先保护原意和作者声音；口语任务校对指代、停顿、时长及视觉配合；审稿定位问题并说明影响，不制造虚假的客观分数。

硬要求限于事实与任务边界：不伪造现实经历、数据和引用，不偷换确定程度，不替用户添加立场。语言规则是可调整的默认目标。每段应有明确作用，必要的解释、过渡和总结可以成立；句长、连词、段落数量及材料件数不设统一门槛。检索只补当前任务必要的公开材料，不能为制造“研究感”扩大范围。用户只要成稿时，直接交成稿；需要训练表达或比较版本时，再给简短说明。

这份整合用于提高表达质量，不能据此判断作者身份，也不承诺通过 AI 检测器。它保留可核对的写作要求，把容易误伤正常表达的硬禁令降为语境检查，避免清除一种模板以后又产生另一种模板。
