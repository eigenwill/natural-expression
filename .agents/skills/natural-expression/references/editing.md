# 改稿与审稿

这里的目标是修复表达问题，并确认没有写顺后失真。不能因为原文像某种模板，就判断它来自 AI；清单只帮助发现可编辑的问题。

## 先锁定不能丢的内容

通读原文，记住独立主张、数据、条件、归因和作者立场。特别留意以下变化：

| 原文承诺 | 容易出现的错误 |
|---|---|
| 可能、据某人说、部分人反馈 | 改成确定事实或普遍结论 |
| 超过、不到、约、仅在某条件下 | 改成精确数量或删除适用条件 |
| 正在、计划、试行、尚未完成 | 改成已经完成或正式全面实施 |
| 与某事有关、先后发生 | 改成因果或推测动机 |
| 被报告、被认为、原因未知 | 补造主语，或把报告者当作判断者 |
| 多项真实功能、要求或结论 | 为了打散排比删掉独立信息 |

普通润色应保留这些承诺。用户明确要求摘要或压缩时，可以筛选，但不能删掉使剩余文字成立的限定。直接引语不为风格改字；如需转述，明确是转述并保留原意。

## 先找结构问题

看每段如何接上上一段。优先处理缺前提、论据不能支持结论、话题跳跃和被重复掩埋的要点。

过渡需要表达真实关系，例如从条件转到结果、从问题转到解决过程。若原稿只给相关数据，却声称某事导致另一事，不能用“因此”加固它；指出因果依据不足，并提出补材料或降低论断的建议。没有授权改变观点时，不悄悄把它换成另一个结论。

去掉一段前，确认它是否承担定义、解释、证明、让步、转场或记忆提示。可以合并同义解释；必要的论证、教学复述和情绪停顿不按“重复”一律删除。

## 再找表达问题

| 检查点 | 何时修改 | 应保留的边界 |
|---|---|---|
| 空铺垫与预告 | 只宣布重要、深入、接下来要讲什么 | 必要导航、礼貌与口头转场 |
| 假对比与假想敌 | 否定一个无人主张的观点来抬高下文 | 真实误解、真实否定和两项有用区别 |
| 同义排比与碎句 | 多项内容其实在说同一个意思 | 独立项目、有意修辞和新的事实 |
| 意义拔高与宣传尾巴 | 没有内容的“里程碑”“无限可能” | 作者真实评价、明确计划和有依据的意义 |
| 借权威 | 用笼统权威掩盖证据缺口 | 原有归因和不确定性；缺来源另行提醒 |
| 长定语与名词化 | 动作被“的”“进行”“实现”包住 | 必要修饰、状态信息和正式术语 |
| 连词、破折号与冒号 | 用作万能连接却未说明关系 | 真实转折、解释、并列、流程和引语 |
| 排版与草稿残留 | 每项装饰性粗体、正文谈改稿过程 | 有用标题、强调、变更说明及文体需要 |

“赋能”“闭环”“关键”“随着”等词不是自动删除对象。要看它有没有准确含义，是否重复，是否适合当前读者。未知施事者可以使用被动句；正常四字格和三个真实项目可以原样保留。

中文稿按用户或目标文体使用中文标点。不套用英文标题大小写、弯引号或连字符规范。代码和数据中的符号按其格式保护。

## 对照示例

**原句：** 部分试用者认为，新界面可能更容易上手，但目前没有正式测试；移动端计划下个月开放。

**可改：** 部分试用者觉得新界面可能更容易上手，目前还没有正式测试。移动端计划下个月开放。

**失真改法：** 测试表明新界面更易用，移动端下个月上线。

失真版制造了测试结论、丢掉“部分”和“可能”，还把计划强化成承诺。第一版改动很小也可以成立。

**原句：** 错误只发生在导出时，不发生在保存时。导出支持 PDF、PNG 和 SVG。

两句可保留。否定划定了问题范围，三项格式各有独立信息；不为打破句式删去其中一项。

**风格样本：** “我写方案时喜欢先列清单。以前我做过三次现场测试。”

若用它润色另一份方案，可以借鉴清单式组织，不能把“三次现场测试”移到新稿。类似地，轻松样本不能授权替作者写“我当时特别激动”。

## 怎样给审稿结果

按影响理解的程度排序，不必给每段打分。先说明最重要的问题，然后为每处给出“位置或短引文、为什么有问题、怎样修”。区分论证缺口、表达不清和可选风格调整；不把编辑判断描述成准确的读者流失预测。

短稿不必制作大型报告。长稿的段落表仅在确实便于定位时使用。用户只要检查时，局部替代句是建议，不直接覆盖整篇。用户要求改稿时，默认净稿；对照格式按需提供，不反复请求已有授权。

## 文件与最后核对

修改文件前区分散文正文与机器可读内容。代码、命令、路径、URL、数据、元信息和显式 ID 保持原样；默认保护已有标题锚点、表格单元信息和有意义的列表顺序。需要改标题或移动内容时，检查相关引用。

完成后将稿件与原文逐项核对。每个新增信息来自哪里？是否丢掉独立主张、否定、条件、时间、范围、比较、归因或作者意见？有没有把草稿样本中的事实带入？最后才检查节奏与排版。

若没有实质问题，允许交付“这一段已经清楚，可以保留”。不以改动数量证明工作价值。
